# FetchPickAndPlace DDPG+HER+SABER Replay-Action Query LS512

This package is the strict matched replay-action-query ablation of the completed
FetchPickAndPlace DDPG+HER+SABER v4 LS512 Main experiment.

## Scientific contract

The canonical reference is
`experiment_FPP/b3_critic_only_runtime_opt_v4_ls512`.  The only scientific
configuration change is:

| Field | Main SABER | This arm |
|---|---|---|
| `support_query_mode` | implicit default `current_policy` | `replay_action` |

The only other `config.json` differences are the registered identifiers
`folder`, `run_slug`, `output_root`, `purpose`, and `reference`.  The package
keeps DDPG, critic-only batch-normalized SABER weighting, uniform replay
sampling, future-goal HER, sparse rewards, Bellman targets, actor objective,
network/optimizer settings, update budget, bounded deterministic-tail support
scan, cache behavior, and Numba scanner settings fixed.

For sample `i`, the support predicate receives the exact executed action stored
in `batch.action_exec[i]`.  That action is not copied into another sample,
shuffled, noised, regenerated by the actor, or used to alter rewards or targets.
Critic Bellman regression continues to use the same replay action.  Minibatch
membership and local candidate-pool membership are unchanged; this is not a
replay sampling or prioritization experiment.

Replay-action querying retains the sampled transition in the local replay pool and can therefore self-support.

No leave-one-out rule is applied.  Self-support remains subject to the same
bounded scan, full-context filter, and population thresholds, so a support
positive rate of one is neither expected nor used as a completion gate.

## Tests

```bash
bash experiment_FPP/ddpg_saber_query_replay_ls512/run_tests.sh
```

The suite covers replay-action identity/non-mutation and query-bin equality,
sample/context/HER/horizon ordering, critic/actor routing, self-support without
leave-one-out, under-populated negative cases, cached/uncached and
Numba/reference parity, cache-key mode separation, invalid-mode failure, and
current-policy legacy parity.

## 20k seed-1 smoke

This is a real 20,000-step run and deliberately does not use trainer `--smoke`:

```bash
DEVICE=cuda \
  bash experiment_FPP/ddpg_saber_query_replay_ls512/run_smoke_20k_seed1.sh
```

The launcher runs tests first and then applies the strict smoke completion gate.
Smoke output never enters the 1M result root.

## Main 1M seeds 1--5

Run only after the tested source commit is on `origin/main`:

```bash
MAX_PARALLEL=2 DEVICE=cuda \
  bash experiment_FPP/ddpg_saber_query_replay_ls512/run_main_1m_seeds1_5_parallel.sh
```

`MAX_PARALLEL` is restricted to one or two workers and defaults to two.  The
launcher preserves the canonical thread environment, refuses existing targets,
records source/repository provenance and one log per seed, and refuses
to train unless the worktree is clean and `HEAD == origin/main`.  It validates
all five outputs after successful process completion.

## No resume or tuning

Resume is intentionally unsupported.  Do not reuse partial run directories,
change a setting after observing results, run a screening arm, or substitute
PER/HGR/replay-selection logic.  Failed seeds must restart in clean registered
targets with the frozen source/config.

`run_all_seeds.sh` and `run_screening_3seeds_parallel.sh` are disabled
compatibility stubs; they cannot launch alternate budgets or tuning runs.
